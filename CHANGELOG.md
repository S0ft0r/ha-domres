# История изменений

## [0.1.12] — доступность сенсоров, перенастройка и порог срока

- Исправлена ошибка запуска платформы сенсоров: добавлен импорт домена интеграции, из-за отсутствия которого существующие сенсоры оставались недоступны.
- Добавлен поток «Перенастроить» для обновления пароля и заголовка API существующей записи без удаления интеграции.
- Имя сенсора последних показаний сокращено до «Последние показания»; при запуске мигрируются старые автоматически сформированные имена, но сохраняются пользовательские.
- Диапазон порога события срока подачи ограничен 1–7 днями; прежние сохранённые значения нормализуются до допустимого значения при загрузке, а форма настройки предлагает уже ограниченное значение.
- Сенсор задолженности переименован в «К оплате»; обновлены иконки баланса, пеней и кнопки подготовки показания.
- Имена кнопки и числового поля сокращены до «Отправить» и «Показание».

---

## [0.1.11] — запрет уменьшения показаний

- Нижняя граница поля ввода и отдельная проверка кнопки не позволяют подготовить/отправить значение меньше последнего показания счётчика.

---

## [0.1.10] — дедупликация события по периоду передачи

- Добавлен read-only запрос `/indications/status`; `domres_unpaid_bill` теперь формируется не более одного раза за период `datePeriodFrom`–`datePeriodTo` и может возникнуть в новом периоде.
- Последний период уведомления сохраняется между перезапусками Home Assistant; обнуление баланса в том же периоде событие не перевооружает.

---

## [0.1.9] — одноразовое событие неоплаченного счёта

- Событие `domres_unpaid_bill` больше не перевооружается после обнуления или отрицательного баланса; за одну загрузку интеграции оно формируется не более одного раза на лицевой счёт.

---

## [0.1.8] — события по сроку и задолженности, поля ввода показаний

- Добавлена настройка порога за 0–31 день до конца периода (по умолчанию 3) и событие `domres_reading_deadline` один раз на лицевой счёт при входе в порог.
- Добавлено событие `domres_unpaid_bill` при переходе баланса счёта в положительную задолженность.
- Добавлены числовые поля и кнопки отправки для каждого тарифа. Кнопка пока намеренно не выполняет запрос: endpoint отправки не подтверждён.

---

## [0.1.7] — короткое имя сенсора последних показаний

- Friendly name сенсора последних показаний сокращён до «Последние показания» без названия счётчика и тарифа.

---

## [0.1.6] — безопасное восстановление архива при отсутствии build-state

- При отсутствии build-state текущий незатегированный архив переиспользуется только при точном совпадении с delta от последнего тега; иначе он атомарно пересобирается.
- Архив уже помеченной тегом версии через восстановительный путь не перезаписывается.

---

## [0.1.5] — delta-сборка по последнему релизному тегу

- Если build-state отсутствует, release workflow строит delta от последнего корректного `v0.1.N` тега вместо отказа; пропуск промежуточных patch-версий поддерживается.
- Добавлены тесты сравнения с тегом и публикации версии после пропуска номера.

---

## [0.1.4] — улучшен сенсор дней периода

- Количество дней передаётся в Home Assistant как целое число; единица отображается по-русски с формой «день/дня/дней».
- Удалён бинарный сенсор доступности передачи показаний; при настройке удаляется его устаревшая запись из реестра сущностей.

---

## [0.1.3] — упрощена публикация релиза

- Удалена фиксированная двухминутная пауза в release workflow; перед подготовкой релиза сразу проверяется, что `main` всё ещё указывает на проверенный commit.
- Добавлены предоставленные владельцем `codeowners`, ссылки на документацию и issue tracker в manifest.

---

## [0.1.2] — раздельная проверка исходников и состояния релиза

- Обычные GitHub Actions-проверки больше не требуют наличия ранее собранного release-архива; строгая проверка запускается только после подготовки архива.
- Для самого первого выпуска release workflow создаёт baseline-архив на текущей версии manifest. Если релизные теги уже существуют, но build-state отсутствует, публикация останавливается, чтобы не выдавать полный снимок за delta.
- Добавлен тест CI-bootstrap сборщика и статические проверки отсутствия циклической зависимости в workflow.

---

## [0.1.1] — усиление проверок и обработка ошибок

- Ошибки авторизации и сетевого соединения больше не поглощаются как ошибки отдельных необязательных запросов; если все чтения лицевого счёта не удались, обновление помечается неуспешным.
- Убран широкий `except Exception` из настройки записи конфигурации, чтобы ошибки программирования не маскировались под временную недоступность API.
- Усилен локальный валидатор: проверка совпадения Config Flow/API-методов, отсутствие синхронного файлового I/O и широких обработчиков исключений, а также наличие и версионные ограничения сторонних зависимостей.
- Релизный workflow запускается только на `main`, ждёт успешных local/Hassfest/HACS-проверок, проверяет метаданные, номер версии и актуальность commit; ручной запуск и push тега не публикуют релиз.
- Добавлены тесты обработки сетевых ошибок, проверки методов Config Flow и запрета повторной публикации версии.

---

## [0.1.0] — начальная read-only версия

- Добавлена интеграция Home Assistant с одним полем телефона/email и автоматическим определением типа логина.
- Добавлены сущности для баланса, пеней, периода передачи показаний и распознанных последних показаний.
- Реализованы только авторизация и чтение данных; отправки показаний нет.
- Добавлены локальный валидатор, тесты, delta-сборщик и GitHub Actions.
