# ДомРесурс для Home Assistant

Кастомная интеграция для отображения данных личного кабинета ДомРесурса в Home Assistant. Первая версия работает **только на чтение**: она не отправляет и не изменяет показания.

## Доступные сущности

Для каждого найденного лицевого счёта создаются:

- сенсор задолженности — значение `balance.value` из сводки баланса;
- сенсор пеней — значение `fine.value` из той же сводки;
- количество дней до конца периода передачи показаний;
- бинарный сенсор доступности передачи показаний;
- сенсоры последних показаний по тарифам/шкалам, если их значения и единицы удаётся распознать в ответе прибора учёта.

Сумма задолженности и пеней не рассчитывается: оба поля показываются отдельно. Ненулевой знак и смысл `balance.value` пока не подтверждены на реальном ненулевом балансе. Для текущего случая с нулевыми значениями личный кабинет показывал отсутствие задолженности.

## Установка вручную

1. Скопируйте каталог `custom_components/domres` в каталог `custom_components` вашей установки Home Assistant.
2. Перезапустите Home Assistant.
3. Откройте **Настройки → Устройства и службы → Добавить интеграцию** и выберите **ДомРесурс**.
4. Введите телефон **или** email, использовавшийся при регистрации, и пароль. Тип логина определяется автоматически.

Поле **Customer-заголовок API** необязательное. Оставьте его пустым, если значение для вашей учётной записи не подтверждено. Публичный клиент для Псковэнергосбыта использует `Customer: ikus-mes`, однако это не доказывает, что такой заголовок подходит другим учётным записям. Если вход не проходит, проверьте заголовок `Customer` в собственном запросе авторизации в инструментах разработчика браузера.

## Данные и ограничения

Интеграция использует авторизацию `POST /api/v8/users/auth` и GET-запросы:

- `/api/v8/accounts/light` — список лицевых счетов;
- `/api/v1/accounts/{accountId}/balance/summary` — баланс и пени;
- `/api/v1/accounts/{accountId}/indications/after-days` — доступность и число дней;
- `/api/v6/accounts/{accountId}/meters/info` — сведения о приборах и последних показаниях.

Формы ответов для сводки баланса и периода наблюдались в личном кабинете. Ответ прибора учёта может различаться; неизвестные единицы не получают неподходящий класс устройства. Если сервер запросит дополнительную проверку входа, настройка сообщит об этом — такой сценарий пока не поддержан.

Обновление данных выполняется раз в 6 часов. Токен повторно запрашивается после ответа HTTP 401. Логин, пароль и токен не записываются в журналы интеграции. Учётные данные хранятся в стандартной записи конфигурации Home Assistant.

## Сборка и проверка

Из корня проекта:

```bash
python scripts/validate.py
python -m unittest discover -s tests -v
python scripts/build_release.py
```

Скрипт сборки проверяет номер версии `0.1.N`, автоматически увеличивает `N` при изменениях после предыдущей сборки и сохраняет архив изменённых файлов в `release/`. Первый архив включает весь компонент, локальный валидатор, тесты и GitHub Actions. Архивы предыдущих сборок не удаляются. В архивы не включаются внутренние заметки и файлы вне списка публичной упаковки.

Для создания ZIP только с интеграцией (папка `domres/` внутри архива):

```bash
python scripts/build_release.py --component-zip domres.zip
```

GitHub Actions запускает локальные проверки и Hassfest. HACS validation автоматически включится после добавления выбранного файла лицензии; публикация GitHub-релиза выполняется по тегу `v0.1.N`.
