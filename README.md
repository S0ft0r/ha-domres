# ДомРесурс для Home Assistant

Кастомная интеграция для данных личного кабинета ДомРесурса в Home Assistant. API-часть интеграции работает **только на чтение**: запросы пока только читают данные. Для подготовки показаний созданы локальные поля и кнопки, но кнопки намеренно не отправляют запросы до подтверждения контракта API.

## Доступные сущности

Для каждого найденного лицевого счёта создаются:

- сенсор «К оплате» — значение `balance.value` из сводки баланса;
- сенсор пеней — значение `fine.value` из той же сводки;
- целое количество дней до конца периода передачи показаний с русской формой единицы «день/дня/дней»;
- сенсоры последних показаний по тарифам/шкалам, если их значения и единицы удаётся распознать в ответе прибора учёта; их имя — «Последние показания»;
- числовое поле для подготовки нового значения и кнопка на каждый тариф/шкалу. Минимум поля равен последнему показанию; более низкое значение блокируется также при нажатии кнопки. Введённое значение хранится только в памяти до перезапуска Home Assistant; кнопка пока сообщает, что отправка отключена.

Сумма задолженности и пеней не рассчитывается: оба поля показываются отдельно. По выбранному правилу положительное `balance.value` считается неоплаченной задолженностью; поле `fine.value` передаётся в payload события отдельно.

## События и подготовка показаний

Порог уведомления о сроке подачи настраивается в параметрах интеграции: от 1 до 7 дней, по умолчанию 3. При входе в этот порог для лицевого счёта один раз за активный период возникает событие `domres_reading_deadline` с `entry_id`, `account_id`, `account_name`, `days_remaining`, `deadline_days` и `period_title`. Повторные обновления данных событие не повторяют; после выхода за порог оно будет вооружено для следующего периода. Если Home Assistant перезапустить, пока событие ещё активно, оно может возникнуть повторно.

Событие `domres_unpaid_bill` возникает при положительном балансе один раз на период `datePeriodFrom`–`datePeriodTo` из `/indications/status`. В payload входят `entry_id`, `account_id`, `account_name`, `balance`, `fine`, `period_from` и `period_to`. Обнуление/отрицательное значение не вызывает повтор в том же периоде; в новом периоде событие снова возможно. Последний уведомлённый период сохраняется в хранилище Home Assistant и переживает перезапуск.

Поля ввода и кнопки созданы отдельно для каждой шкалы. Кнопка пока намеренно заблокирована: её нажатие не выполняет сетевой запрос, а сообщает, что отправка ещё не включена. Перед подключением POST нужно подтвердить endpoint и формат тела запроса; живые тестовые показания не отправляются.

## Установка вручную

1. Скопируйте каталог `custom_components/domres` в каталог `custom_components` вашей установки Home Assistant.
2. Перезапустите Home Assistant.
3. Откройте **Настройки → Устройства и службы → Добавить интеграцию** и выберите **ДомРесурс**.
4. Введите телефон **или** email, использовавшийся при регистрации, и пароль. Тип логина определяется автоматически.

Поле **Customer-заголовок API** необязательное. Оставьте его пустым, если значение для вашей учётной записи не подтверждено. Публичный клиент для Псковэнергосбыта использует `Customer: ikus-mes`, однако это не доказывает, что такой заголовок подходит другим учётным записям. Если вход не проходит, проверьте заголовок `Customer` в собственном запросе авторизации в инструментах разработчика браузера.

## Данные и ограничения

Интеграция использует авторизацию `POST /api/v8/users/auth` и GET-запросы:

- `/api/v8/accounts/light` — список лицевых счетов;
- `/api/v1/accounts/{accountId}/balance/summary` — баланс и пени;
- `/api/v1/accounts/{accountId}/indications/after-days` — доступность и число дней;
- `/api/v1/accounts/{accountId}/indications/status` — статус и границы периода передачи показаний;
- `/api/v6/accounts/{accountId}/meters/info` — сведения о приборах и последних показаниях.

Формы ответов для сводки баланса и периода наблюдались в личном кабинете. Ответ прибора учёта может различаться; неизвестные единицы не получают неподходящий класс устройства. Если сервер запросит дополнительную проверку входа, настройка сообщит об этом — такой сценарий пока не поддержан.

Обновление данных выполняется раз в 6 часов. Токен повторно запрашивается после ответа HTTP 401. Логин, пароль и токен не записываются в журналы интеграции. Учётные данные хранятся в стандартной записи конфигурации Home Assistant.
